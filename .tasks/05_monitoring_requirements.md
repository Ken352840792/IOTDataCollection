# 系统监控需求规范

## 📊 监控功能概述

系统监控模块提供采集端设备的实时资源监控、性能分析和告警功能，包含独立的监控仪表板界面。

## 🎯 核心监控功能

### 1. 系统资源监控
- **CPU使用率**: 实时监控CPU占用百分比
- **内存使用率**: 监控内存占用和可用内存
- **磁盘使用率**: 监控磁盘空间占用情况
- **网络流量**: 监控网络发送/接收速度

### 2. 设备状态监控
- **设备连接状态**: 在线/离线/错误/维护
- **通信延迟**: 设备响应时间监控
- **数据采集状态**: 采集成功率和失败率
- **服务运行状态**: 采集服务健康状态

### 3. 告警管理
- **阈值告警**: 资源使用率超过预设阈值
- **状态告警**: 设备连接异常或服务故障
- **趋势告警**: 资源使用趋势异常预警
- **告警历史**: 历史告警记录和处理状态

## 📊 监控配置规范

### 监控频率配置
- **采集间隔**: 30秒（默认配置）
- **数据保留**: 监控数据保留3个月
- **告警检查**: 每次数据采集时检查告警条件
- **界面刷新**: 监控界面30秒自动刷新

### 告警阈值配置
```yaml
默认告警阈值:
  CPU使用率: 80%
  内存使用率: 85% 
  磁盘使用率: 90%
  网络流量: 100MB/s
  
告警级别:
  正常: green (低于阈值)
  警告: orange (达到阈值)
  严重: red (超过阈值10%)
```

## 🏗️ 监控领域模型设计

### 采集节点聚合根
**核心职责**：管理采集端的系统资源监控和告警评估
- **聚合根**：CollectorNode（采集节点）
- **实体**：SystemMetric（系统指标）、PerformanceCounter（性能计数器）
- **值对象**：SystemResources（系统资源）、ResourceUsage（资源使用率）、AlertThreshold（告警阈值）

**业务规则**：
- 系统资源每30秒采集一次
- 连续3个周期超过阈值才触发告警
- 告警状态变更需要记录历史
- 监控配置支持热更新

### 系统资源监控模型
**数据结构设计**：
- **CPU使用率**：包含使用百分比和温度信息
- **内存使用率**：包含使用百分比、可用内存、总内存
- **磁盘使用率**：包含使用百分比、可用空间、总空间
- **网络使用**：包含网络速度、发送量、接收量

**监控配置模型**：
- 支持按设备独立配置告警阈值
- 支持监控功能的启用/禁用控制
- 支持采集间隔的动态调整

**界面展示模式**：

- **列表视图**：表格式展示，适合详细对比
- **图表视图**：图表式展示，适合趋势分析

### 2. 监控界面布局设计

## 📊 监控数据存储

### InfluxDB时序数据设计
**系统资源监控数据表**：
- **Tags**：device_code（设备编码）、metric_type（指标类型）
- **Fields**：cpu_usage（CPU使用率）、memory_usage（内存使用率）、disk_usage（磁盘使用率）、network_speed（网络速度）
- **用途**：存储采集端系统资源使用情况

**告警记录数据表**：
- **Tags**：device_code（设备编码）、alert_type（告警类型）、alert_level（告警级别）
- **Fields**：threshold_value（阈值）、actual_value（实际值）、resolved（是否已解决）
- **用途**：存储系统告警记录和处理历史

**设备状态变更数据表**：
- **Tags**：device_code（设备编码）、old_status（原状态）、new_status（新状态）、reason（变更原因）
- **Fields**：状态变更的详细信息
- **用途**：记录设备状态变更历史

### MySQL配置表结构
**监控配置表 T_MONITORING_CONFIGS**：
- **F_DEVICE_CODE**：设备编码（外键，唯一）
- **F_COLLECTION_INTERVAL**：采集间隔（默认30秒）
- **F_CPU_THRESHOLD**：CPU告警阈值（默认80%）
- **F_MEMORY_THRESHOLD**：内存告警阈值（默认85%）
- **F_DISK_THRESHOLD**：磁盘告警阈值（默认90%）
- **F_NETWORK_THRESHOLD**：网络流量阈值（默认100MB/s）
- **F_IS_ENABLED**：是否启用监控（默认启用）
- **F_AUTO_RESTART**：是否自动重启（可选功能）

## 🔔 告警处理流程

### 告警触发条件
1. **资源告警**: CPU/内存/磁盘使用率超过阈值
2. **连接告警**: 设备连接中断超过3个监控周期
3. **采集告警**: 数据采集失败率超过50%
4. **服务告警**: 采集服务进程异常退出

### 告警处理机制
**告警等级分类**：
- **信息级别**：蓝色标识，优先级1，一般性信息通知
- **警告级别**：橙色标识，优先级2，需要关注的资源使用情况
- **错误级别**：红色标识，优先级3，需要及时处理的问题
- **严重级别**：紫色标识，优先级4，需要立即处理的严重问题

**告警通知方式**（当前仅界面显示）：
- **仪表板标记**：在监控仪表板显示红色告警标记
- **弹窗提醒**：重要告警时弹窗提醒用户
- **声音提醒**：可选功能，告警时播放提示音
- **邮件通知**：未来扩展功能，支持邮件告警

**告警抑制规则**：
- **重复告警抑制**：5分钟内相同类型告警不重复发送
- **告警数量限制**：单设备最大活跃告警数为10个
- **告警级联控制**：避免因单一问题产生大量重复告警
